# Локальная проверка CSAI-3210 — 26 октября 2026

> Исторический отчёт до расширения датасета. Актуальная разметка: 52 кропа,
> 37 групп автомобилей; текущие исправления и ограничения — в DATA_AUDIT.md.
> Пункты ниже о 23 кропах и неизменённом коде относятся к предыдущему этапу.

Проверены README.md, DATA_AUDIT.md, project.py, prepare_reviewed.py,
requirements.txt, label_review.csv, data/labels.csv и review_summary.json.
Полноценное обучение не запускалось. Тест GPU не измеряет точность.

## Данные

В проекте 76 исходных фотографий и 23 размеченных кропа, 17 групп физических
автомобилей, 11 марок. Представлены только black (8), grey (7), white (8).
Нет red, blue, green, brown, yellow. Повторные ракурсы одного автомобиля не
являются независимыми примерами.

Данных недостаточно для достоверной классификации 11 марок и восьми цветов.
Для марок с единственным автомобилем невозможно одновременно получить
независимые обучающие и проверочные примеры. Дополнительные 53 фотографии
не становятся размеченными автоматически. Кандидаты medium в label_review.csv
требуют ручного подтверждения; Aion уже включён в исходную разметку, хотя в
списке кандидатов он отмечен medium. Код не подтверждает правильность марки.

Нужно собирать независимые автомобили каждой целевой марки, разные цвета,
ракурсы и освещение. Практический начальный ориентир — десятки независимых
машин на марку, лучше 50–100 и более, с отдельными машинами для проверки;
это ориентир для сбора, а не гарантия точности. Для отсутствующих цветов
нужны реальные проверенные примеры. Аугментация не заменяет независимые машины.

## Обнаруженные проблемы кода

1. `label()` считает `source` абсолютным путём фотографии, тогда как текущая
   разметка использует идентификатор автомобиля. Повторная разметка имеющихся
   фотографий не будет пропущена; новые ракурсы одного автомобиля могут попасть
   в разные части выборки. Нужны отдельные поля photo и vehicle_id и явный выбор
   группы при разметке.
2. Имена новых кропов используют нестабильный между процессами Python `hash()`.
   Запись `cv2.imwrite()` не проверяется. Лучше UUID/стабильный идентификатор,
   проверка результата и защита существующего файла.
3. `read_rows()` молча исключает неизвестные цвета, пустые марки и отсутствующие
   файлы. Минимум 10 кропов не проверяет пригодность данных для обучения.
4. `GroupShuffleSplit` защищает группы, но не обеспечивает покрытие всех классов.
   При текущем датасете результат сильно зависит от seed; предупреждение о
   марках, отсутствующих в обучении, не устраняет проблему.
5. `evaluate()` берёт split.json из `--out`, независимо от пути checkpoint,
   и использует текущие labels.csv. После изменения разметки состав проверки
   может отличаться от исходного. Нет fingerprint датасета и списка кропов
   внутри checkpoint. Неизвестные марки молча исключаются из оценки, пустая
   проверочная выборка не отклоняется явно.
6. `predict()` рисует рамки и подписи на том же frame, из которого затем берёт
   следующие кропы. При пересечении машин разметка предыдущего объекта может
   попасть во вход классификатора. Нужна отдельная копия для визуализации.
7. `--save` может совпасть с исходным изображением; защиты от перезаписи нет.
   Результат сохранения также не проверяется. В ходе этого аудита predict с
   сохранением поверх оригинала не запускался.
8. `prepare_reviewed.py` перезаписывает labels.csv и существующие review-кропы
   без подтверждения. Во время аудита он не запускался.
9. Исходный requirements.txt задаёт широкие диапазоны и не гарантирует CUDA.
   Локальная установка и снимок зависимостей описаны ниже.

Исходные project.py, prepare_reviewed.py и разметка сохранены без исправлений:
этот этап проверяет существующее поведение и документирует ограничения.
Обученного классификатора в исходном проекте нет; качество распознавания
марок/цветов пока не установлено.

## Фактические результаты проверки

- Python 3.11.9 x64 установлен в `.python/`, виртуальное окружение — `.venv/`.
  Системный PATH не изменялся. Исходный `python` в PATH был недоступной
  заглушкой Windows Store, `py` отсутствовал.
- NVIDIA RTX 4070 SUPER, 12282 MiB по nvidia-smi, драйвер 621.01.
  PyTorch 2.9.1+cu128 и torchvision 0.24.1+cu128, runtime CUDA 12.8;
  `torch.cuda.is_available()` вернул True, вычисление на CUDA прошло.
  Совместимая пара выбрана из официальных команд PyTorch:
  https://pytorch.org/get-started/previous-versions/ . Отдельный CUDA Toolkit
  для запуска этих готовых сборок не устанавливался.
- Все зависимости установлены, `pip check`: No broken requirements found.
  Полный снимок установленных версий — `requirements-lock.txt`.
- Проверка синтаксиса трёх Python-файлов и `project.py --help` прошли.
- Все 76 оригиналов и 23 кропа проверены Pillow (verify и полное декодирование).
  Побайтовых дубликатов не найдено; сходные ракурсы при этом присутствуют.
  SHA-256 всех оригиналов совпал с исходным манифестом `.setup/original_hashes.csv`.
- Просмотрены контактные листы всех оригиналов и кропов. Есть далёкие машины,
  повторные ракурсы, разные условия освещения. `review_39.jpg` заметно обрезает
  целевой автомобиль; `review_56.jpg` выглядит бежевым/тёплым при метке white.
  Нужна повторная ручная проверка этих кропов; метки автоматически не менялись.
- В split при seed=42: 15 обучающих и 8 проверочных кропов, пересечения групп
  нет. Aion, BMW, Voyah есть только в проверке. Только BYD встречается в обеих
  частях. Из 11 марок у девяти всего одна независимая машина; у BYD и Chevrolet
  по четыре. Даже три кропа Aion представляют один автомобиль.
- Все элементы CarDataset преобразуются в конечные тензоры 3×224×224.
  RegNet с ImageNet backbone прошёл forward/backward на CUDA, batch=2,
  без optimizer.step(). Сохранение и загрузка временного checkpoint прошли.
- Загружены RegNet backbone в `.cache/torch/` и COCO `yolo11n.pt` в корень.
  Детектор прошёл GPU-инференс на photo_10 и вернул одну рамку класса car.
  Это результат одного функционального теста, а не оценка качества детектора.
- Реальная функция `predict()` прошла тест с временным checkpoint с
  необученными головами. Его текстовые ответы скрыты, временные веса и
  производное изображение удалены. Готового обученного `best.pt` нет.
- Повторный тест с уже закешированными весами прошёл в обычной ограниченной
  среде без повторного разрешения сети. Полностью изолированный тест с
  физически отключённым Wi-Fi и GUI-разметка вручную не проводились.
- Обнаружена дополнительная Windows-проблема: чистый `cv2.imread()` не читает
  абсолютный путь с кириллицей в имени текущей папки. В `predict()` импорт
  Ultralytics подменяет функцию чтения и тест проходит, но `label()` с
  абсолютным кириллическим путём без этого импорта может пропускать снимки.
  Надёжное исправление — собственное чтение через Pillow либо
  `cv2.imdecode(np.fromfile(...), ...)`, аналогично для записи.

## Использование окружения

Из корня проекта в PowerShell (активация окружения не обязательна):

```powershell
$env:TORCH_HOME = Join-Path $PWD '.cache/torch'
$env:YOLO_CONFIG_DIR = Join-Path $PWD '.cache/ultralytics'
.\.venv\Scripts\python.exe project.py --help
.\.venv\Scripts\python.exe smoke_check.py
.\.venv\Scripts\python.exe -m pip check
```

Или `./run-project.ps1 --help`: обёртка сама задаёт пути кешей.
Команда train намеренно не запускалась.

Воспроизведение зависимостей в другом Python 3.11 venv:

```powershell
python -m pip install -r requirements-lock.txt --extra-index-url https://download.pytorch.org/whl/cu128
```

Результат smoke-теста сохранён в `checks/smoke_results.json`, журнал —
`checks/smoke_log.txt`, контактные листы — `checks/contact_*.jpg` и
`checks/crops_contact.jpg`. Контактные листы — отдельные производные файлы.
Метки, оригиналы и существующие кропы не изменялись. Метрики точности не
вычислялись и не заявляются. Batch=24 для полноценного обучения не проверен;
малый smoke batch не доказывает его требования к памяти.
